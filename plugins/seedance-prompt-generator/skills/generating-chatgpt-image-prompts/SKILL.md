# ChatGPT Images 2.0 提示词

将用户需求写成可直接提交给 ChatGPT Images 2.0 的提示词。保持自然语言清楚、直接、可执行；不要混入 Seedance 或 Nano Banana 的工作流、术语或参数。

## 工作流

1. 判断任务：文生图、精准编辑、多参考图、人物一致性、商品图、图片文字、透明背景素材、信息图，或“做成模板”。普通生图需求只有在用户明确面向 ChatGPT 或 OpenAI 时才使用本技能。
2. 阅读 [ChatGPT Images 指南](references/chatgpt-images-guide.md)。仅在需要具体壳层时，阅读 [模板](references/templates.md) 中相应小节。
3. 从需求中提取用途、主体、动作、环境、构图、风格、光线、约束和画幅比例；信息缺失时作保守补全，不虚构平台参数。
4. 先写提示词主体：简单任务写成 1–3 句完整自然语言；复杂商业任务可用短段落或清晰字段。默认不输出 JSON。
5. 有参考图时，按上传顺序写明每张图的职责和不继承内容；只保留少量确有作用的参考图。
6. 精准编辑时，使用“只修改 [指定区域]；其余全部保持不变”的语法，明确保留人物、构图、光线、材质、文字和画幅中适用的项目。
7. 图片内文字必须逐字加引号，并指定字体气质、大小、颜色、位置；要求不出现额外文字、乱码或水印。
8. 后续迭代一次只改一个变量；其余要求沿用上一版，避免重新解释整张图。
9. 使用 `compact`、`standard`、`detailed` 控制复杂度；用户要求精简时删除重复描述与无关约束。负面约束只为当前任务动态生成。

## 输出契约

除非用户明确要求“只给提示词”，否则严格按以下六栏交付：

1. `【提示词成品】`：可直接复制的最终提示词。
2. `【负面约束】`：只列出当前任务相关的防跑偏要求。
3. `【参考图绑定】`：逐图职责、排除项；无参考图写“无”。
4. `【参数建议】`：写平台、任务类型、画幅与必要设置；没有官方确认的参数不要编造。
5. `【风格锚点】`：可稳定复用的审美、材质、光线和版式规则。
6. `【一致性检查】`：检查主体、参考图、文字、构图、光线，以及人体或商品结构。

只有用户明确说“保存成模板”“给我复用短句”“以后继续用这个风格”“做成可复用版本”或“下次沿用这套结构”时，才追加 `【下次可复用短句】`；普通任务不输出。

用户明确要求“只给提示词”时，只输出 `【提示词成品】`，不附加其他栏目。用户要求“做成模板”时，用 `[主体]`、`[场景]`、`[动作]`、`[镜头景别]`、`[视角]`、`[画幅比例]`、`[道具]`、`[卖点]` 等可理解的占位符，不遗留内部字段。

## 专项规则

- **文生图**：按“用途 → 主体 → 动作 → 环境 → 构图 → 风格 → 光线 → 约束 → 画幅比例”组织；不要堆砌互相冲突的风格词。
- **精准编辑**：只修改用户点名的对象或区域；其他一律保持不变。若范围不清，采用最小修改范围，并在参考图绑定中说明假设。
- **多参考图**：用“图 1 锁定……；图 2 仅参考……，不继承……”逐图绑定；不要默认混合所有图的身份、姿势、背景与配色。
- **人物一致性**：锁定脸部结构、年龄感、自然肤质、发型和可识别特征；除非用户明确要求，不自动美化、年轻化或重塑面部。
- **商品与品牌**：锁定包装结构、比例、标签、Logo 位置和品牌色；除非用户指定，不改写品牌文案。
- **透明背景**：明确要求真实透明背景、完整主体边缘、无地面、无投影、无环境元素；不声称平台有未确认的导出开关。
- **信息图**：先保证信息层级、短文案和可读性，再补视觉风格；文字内容必须逐字引号标注。
- **多平台需求**：当用户同时指定 ChatGPT Images 2.0 与其他图像平台时，分别输出各平台的独立版本；本技能负责的版本始终标注为 `ChatGPT Images 2.0 版`，且不混写其他平台规则。

## 交付前检查

- 简单任务的提示词是否控制为 1–3 句，且每句都推动结果？
- 是否明确了唯一的编辑范围，并写出其余不变？
- 参考图是否职责单一、数量克制、无冲突？
- 图片文字是否逐字引用，并含位置、颜色、大小与字体气质？
- 是否避免 JSON、虚构参数和不必要的长篇解释？

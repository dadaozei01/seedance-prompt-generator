# 多平台提示词生成 Skill 扩展设计

日期：2026-08-06

## 目标

在现有 `seedance-prompt-generator` Codex 插件中新增 Nano Banana 与 ChatGPT Images 2.0 两套图片提示词生成能力，同时完整保留现有 Seedance 2.0/2.5 视频提示词能力和既有触发方式。

最终插件应根据用户明确提到的平台自动调用对应 Skill。三套平台规则相互隔离，不把不同平台的格式、参数或提示策略混合到同一份成品中。

## 范围

本次包含：

- 保留并兼容现有 `generating-seedance-prompts` Skill。
- 新增 `generating-nano-banana-prompts` Skill。
- 新增 `generating-chatgpt-image-prompts` Skill。
- 更新插件元数据、默认示例、README 和版本号。
- 修复仓库内现有文本的中文编码问题。
- 增加静态结构、触发词、引用路径和输出契约验证。

本次不包含：

- 调用 Gemini 或 OpenAI API 实际生成图片。
- 创建网页界面或独立应用。
- 改变 Seedance 现有输出能力、时间轴规则或素材绑定语法。
- 把三个 Skill 合并为一个共享的大型提示词文件。

## 插件结构

插件继续使用原仓库、插件标识和安装入口，避免破坏已有安装与 GitHub 链接。

```text
plugins/seedance-prompt-generator/
├── .codex-plugin/plugin.json
├── assets/
├── skills/
│   ├── generating-seedance-prompts/
│   │   ├── SKILL.md
│   │   └── references/
│   ├── generating-nano-banana-prompts/
│   │   ├── SKILL.md
│   │   └── references/
│   └── generating-chatgpt-image-prompts/
│       ├── SKILL.md
│       └── references/
└── README.md
```

每个 Skill 只拥有自身平台的规则与模板。共通的交付标题可以保持一致，但不建立会导致平台规则串用的共享提示词规则文件。

## 路由规则

### Seedance

- Seedance 2.0、Seedance 2.5
- 即梦、Dreamina
- 视频提示词、图生视频、视频延长、首尾帧、视频编辑

### Nano Banana

以下意图调用 Nano Banana Skill：

- Nano Banana、Nano Banana Pro
- Gemini 生图、Gemini 图片提示词
- 用户明确要求面向 Gemini 的文生图、图片编辑或参考图合成提示词

### ChatGPT Images 2.0

以下意图调用 ChatGPT Images Skill：

- ChatGPT Images 2.0、ChatGPT Image 2、Image 2、Images 2.0
- ChatGPT 生图、OpenAI 图片提示词
- 用户明确要求面向 ChatGPT Images 的文生图或图片编辑提示词

### 未指定平台

如果用户只说“生成图片提示词”而没有平台线索，不自动假定 Nano Banana 或 ChatGPT Images。先提供精简的通用图片提示词成品，并用一句短问题确认目标平台；后续根据用户选择转入对应 Skill。

如果用户同时点名多个平台，则分别输出独立版本，并清楚标注平台，不合并成一段折中提示词。

## Nano Banana Skill

### 核心策略

- 使用完整、连贯的场景描述，而不是标签堆砌。
- 按用途、主体、动作、场景、构图、镜头、光线、风格、材质、文字、输出规格组织信息。
- 多张参考图必须逐张定义职责与排除维度。
- 把不变主体与可变场景分开表达。
- 编辑任务明确“只修改”和“必须保持不变”。
- 人物一致性任务明确面部骨相、五官比例、年龄感、皮肤纹理和不可美化项。
- 复杂任务优先建议在同一会话中进行小步迭代。
- 负面约束优先同时描述期望的正确状态，避免只堆否定关键词。

### 任务类型

- 文生图
- 图片局部编辑
- 多参考图合成
- 人物与人脸一致性
- 商品、包装、Logo 与品牌一致性
- 海报、信息图及图片文字
- 可复用占位符模板

## ChatGPT Images 2.0 Skill

### 核心策略

- 优先使用清晰、直接、紧凑的自然语言。
- 简单需求默认生成 1 至 3 个信息完整的句子；复杂商业任务才使用分段结构。
- 按用途、主体、动作、环境、构图、风格、光线、关键约束和画幅组织信息。
- 精准编辑使用“只改 X，其他内容完全不变”的明确语法。
- 多参考图保持数量精简，按上传顺序说明各图职责。
- 图片文字使用引号给出准确文本，并明确字体、大小、颜色、位置和“无其他文字”。
- 优化采用多轮、单变量、小步修改，重复最重要的不变项以防漂移。
- 不默认输出 JSON 提示词。

### 任务类型

- 文生图
- 图片局部编辑
- 多参考图组合
- 人物与商品一致性
- 透明背景素材、海报、文字设计和信息图
- 可复用占位符模板

## 输出契约

Nano Banana 与 ChatGPT Images 2.0 默认按照以下结构交付：

1. `【提示词成品】`：可以直接复制到目标平台的最终提示词。
2. `【负面约束】`：仅列出与当前任务相关的防跑偏要求。
3. `【参考图绑定】`：逐图说明职责；没有参考图时写“无”。
4. `【参数建议】`：平台、任务类型、画幅及必要设置；不杜撰平台不存在的参数。
5. `【风格锚点】`：提炼可稳定复用的审美与质感规则。
6. `【一致性检查】`：检查主体、参考图、文字、构图、光影、人体或商品结构。
7. `【下次可复用短句】`：提供一条可直接唤起本次规则的短句。

用户明确要求“只给提示词”时，只输出 `【提示词成品】`，不强制附加其他栏目。

用户要求“做成模板”时，使用 `[主体]`、`[场景]`、`[动作]`、`[镜头景别]`、`[视角]`、`[画幅比例]`、`[道具]`、`[卖点]` 等占位符，不遗留未解释的内部字段。

## 编码修复

当前仓库的部分中文内容存在 UTF-8 文本被错误转码后的乱码。实施时应从可验证的中文语义重建受影响文件，并统一保存为无 BOM 或标准 UTF-8。修复不得改变 Seedance 已确定的业务规则。

验证内容包括：

- 文件可按 UTF-8 正确读取。
- YAML frontmatter 和 JSON 均可解析。
- 中文触发词没有乱码替代字符。
- Markdown 内部链接指向存在的文件。

## 验证与验收

### 静态验证

- `plugin.json` 是有效 JSON，版本为 `1.1.0`。
- 三个 Skill 的 `SKILL.md` 均存在，frontmatter 中的 `name` 唯一。
- 每个 Skill 引用的 reference 文件均存在。
- 仓库不存在明显乱码标记或无效 Unicode 替代字符。
- README 准确描述三套能力和调用示例。

### 行为样例验证

使用以下输入人工核对路由和输出：

1. “生成一条 15 秒 Seedance 香水广告提示词。”应只使用视频时间轴与 Seedance 规则。
2. “给我一段 Nano Banana 的咖啡产品海报提示词。”应输出 Gemini 适配的叙事型图片提示词。
3. “生成一段 Image 2 的极简电商主图提示词。”应输出紧凑、直接的 ChatGPT Images 提示词。
4. “用图 1 锁定人物，图 2 参考姿势，生成 Nano Banana 提示词。”应逐图绑定并强化人物一致性。
5. “只把原图沙发改成棕色真皮，Image 2。”应强调局部修改及其他内容不变。
6. “分别给 Nano Banana 和 Image 2 各写一版。”应输出两份独立成品，不混合平台规则。

### 完成标准

- 现有 Seedance 触发与输出继续可用。
- 两个新平台可被明确触发并输出平台专属结果。
- 三套规则相互隔离。
- 中文编码正常。
- 本地验证全部通过。
- 变更提交并推送到原 GitHub 仓库。

## 错误处理

- 平台未指定：先给通用成品，再简短确认目标平台。
- 多参考图职责不清：根据上传顺序做最保守的职责推断，并在 `【参考图绑定】` 中写明假设。
- 缺少画幅或用途：根据内容选择稳定默认值，同时在参数建议中标注。
- 用户要求平台不支持或未被官方确认的精确参数：不编造参数，改为可在提示词中表达的视觉约束。
- 用户需求与平台规则冲突：优先遵循用户明确要求，并提醒可能降低稳定性的部分。
